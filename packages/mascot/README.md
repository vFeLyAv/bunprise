# @bunprise/mascot

Маскоты Bunprise — кролик (главный) и хомяк (друг) — как переиспользуемый код.
Это точный порт прототипов `30-experiments/wishcal-maskot-proto/bunny-v1.html` и
`hamster-v2.html`: те же формы (SVG-«кукла» из слоёв), те же окрасы, те же сцены
и тайминги. Ванильный TypeScript, без зависимостей, работает с любым фреймворком.

## Как устроено

- Маскот монтируется в любой `div`/`span`/custom element через **Shadow DOM** —
  стили приложения не ломают картинку, а стили маскота не вытекают наружу.
- Окрас — это CSS custom properties на хосте (`--mascot-base-top`, `--mascot-accent`, …),
  они проходят сквозь границу Shadow DOM.
- Все id градиентов и clipPath уникальны на каждый экземпляр, поэтому два маскота
  на одной странице не конфликтуют.
- Сцены — цепочки Web Animations (`element.animate`) + CSS-классы состояний; хелпер
  `anim()` ждёт конца анимации и «запоминает» финальный transform.
- `prefers-reduced-motion`: при включённом режиме анимации не запускаются, сцены
  мгновенно переходят в конечное состояние (как в прототипах). Можно принудить:
  `reducedMotion: 'force' | 'off' | 'auto'`.
- Idle-цикл (моргает, косится, дёргает ухом, кролик иногда «настораживается») ставится
  на паузу, когда вкладка скрыта или маскот не виден на экране.
- **Одна сцена за раз.** Вызов `play()` во время другой сцены **игнорируется**
  (промис сразу резолвится) — так было в прототипах. Исключения: собственный idle-нюх уступает любому `play()`; 5 тапов подряд
  ставят «злость» в очередь после текущей сцены.

## API

```ts
import { Bunny, Hamster, createMascot, SCENES, COATS } from '@bunprise/mascot';

const bunny = new Bunny(document.querySelector('#stage')!, {
  coat: 'fawn',          // 'fawn' | 'choc' | 'blue' | 'himalayan' | 'broken'
  ears: 'lop',           // 'lop' | 'upright'
  size: 160,             // ширина сцены в px (высота по пропорции viewBox)
  idle: true,            // idle-цикл
  reducedMotion: 'auto', // 'auto' | 'force' | 'off'
  interactive: true,     // клик по хосту = tap()
});

await bunny.play('greet');   // 'greet' | 'eat' | 'walk' | 'jump' | 'alert' | 'sleep' | 'angry' | 'idle'
bunny.setCoat('himalayan');
bunny.setEars('upright');
bunny.setEyes('star');       // 'normal' | 'star' | 'happy' | 'sleep'
bunny.setPuff(1.2);          // щёки (1 = обычные)
bunny.setSize(240);
bunny.tap();                 // прыжок; 5 тапов за 2,5 с — злится; спящего будит
bunny.hop();                 // маленький подскок (как при смене окраса)
bunny.stopIdle(); bunny.startIdle();
bunny.pose('alert');         // статичная поза для скриншотов (без таймеров)
bunny.destroy();             // убирает всё: таймеры, observers, Shadow DOM

const hamster = createMascot(host, { kind: 'hamster', coat: 'golden' });
// сцены хомяка: 'greet' | 'eat' | 'walk' | 'jump' | 'sleep' | 'angry' | 'secret' | 'speck' | 'idle' (27.10, ниже)

// хомяк держит бинокль (22.10, пустая карточка «Freunde»): своими двумя лапками, обычные лапки на животе скрыты
const lookout = new Hamster(host, { holding: 'binoculars' });
lookout.setHolding(null);    // убрать бинокль; lookout.holding — что держит сейчас
```

`holding: 'binoculars'` — постоянное состояние, как окрас: сцены, `pose()` и `interrupt()` его сохраняют.
Пока идёт idle-цикл, хомяк спокойно оглядывается в бинокль (CSS-цикл 16 с, только transform):
прямо → медленно влево → пауза → вправо, по линзам пробегает блик → в центр → опускает бинокль,
моргает дважды, поднимает с лёгкой пружинкой. Пауза вместе с idle (другой маскот на сцене, вне экрана,
скрытая вкладка); reduced motion — та же поза неподвижно. Моргание и взгляды idle в это время молчат
(глаза за биноклем), ушки живут как обычно.

Состояние: `busy`, `isSleeping`, `scene`, `coat`, `eyes`, `ears` (кролик), `idleRunning`.
События на хосте (всплывают): `mascot-scene-start`, `mascot-scene-end` с `detail: { kind, scene }`.

### Custom element

```html
<bunprise-mascot kind="bunny" coat="choc" ears="up" size="200" scene="greet"></bunprise-mascot>
<bunprise-mascot kind="hamster" coat="robo" idle="false"></bunprise-mascot>
```

Атрибуты: `kind`, `coat`, `ears` (`up`/`lop`, только кролик), `size`, `scene`
(смена атрибута запускает сцену), `idle` (`false` выключает цикл), `reduced-motion`
(`auto`/`force`/`off`). Экземпляр: `el.mascot`.

## Кролики работают: `CarryStage` (волна 1, K10)

После создания повода кролик берёт новую карточку **в зубы**, скачет по изогнутой дорожке туда, где ей место (день в календаре, лента), кладёт её с подскоком, машет лапкой и упрыгивает. Для желания — маленькая коробочка с бантом.

```ts
import { CarryStage } from '@bunprise/mascot';
// host — слой поверх экрана (position: fixed / absolute, inset 0, pointer-events: none); from / to — в его px
const carry = new CarryStage(host, { from, to, item: 'card' | 'gift', tint: '#F7B27A', coat: 'fawn', reducedMotion: 'auto' });
carry.play();
await carry.landed;   // предмет лежит на цели — показать настоящую карточку
await carry.done;     // кролик ушёл
carry.skip();         // сразу к концу (тап); carry.seek(t) — кадр для скриншотов; carry.destroy()
```

- Тот же кролик (3/4 поворот, одобренный цикл прыжков: сплющивание, поджатые лапки, уши, хвостик, тень); предмет — своё маленькое SVG. Одна временная шкала (`Track` → WAAPI), только `transform`/`opacity`, без rAF и таймеров; `seek(t)` точный.
- Хореография: выскакивает из `from` с предметом (≈ 0,3 с) → 2–5 прыжков по кривой (выгнута в сторону взгляда) → встаёт на верхний край цели, предмет падает в её центр с пружинкой (`landedAt` ≈ 2,4 с) → звёздные глаза, ушки, два взмаха лапкой (одобренный `greet`) → 2–3 прыжка вперёд за край слоя (всего ≈ 4,2 с). Предмет на цели тает через 0,5 с (под ним уже настоящий).
- `reducedMotion: 'force'` (или ОС при `auto`): кролика нет — предмет просто плавно доезжает до цели и тает (≈ 0,6 с).
- В приложении: `apps/web/src/features/mascot-ui/carry.ts` (`playCarry` / `useCarry`): уровень движения, один маскот за раз, любой тап = `skip()`.

## Приветственная сцена: `WelcomeStage`

Идея Кирилла (20.10): несколько кроликов разных окрасов вылезают из-за края экрана, цепляясь
лапками, оглядываются, прячутся обратно, один перебегает — а в конце главный (кремовый) кролик
выглядывает снизу по центру и машет лапкой. Это «живая» версия иконки приложения
(`apps/web/public/icons/icon.svg`: кролик держится лапками за край).

Кролики — **тот же персонаж**, что и маскот: та же SVG-кукла (`bunnyMarkup`), те же стили и точки
вращения (`BUNNY_CSS`), те же окрасы, тот же поворот 3/4 и цикл прыжков, «нюхает» = сцена `alert`,
«машет» = сцена `greet`. Лапки «держится за край» — из иконки. Новое только то, как они двигаются
относительно края.

### Быстрый старт

```ts
import { WelcomeStage } from '@bunprise/mascot';

const stage = new WelcomeStage(document.querySelector('#hero')!, {
  bunnies: ['fawn', 'himalayan', 'choc', 'broken'], // по порядку появления, [0] — главный (по умолчанию так и есть)
  choreography: 'welcome',      // или 'peek-once' | 'peek-bottom' | 'peek-left' | 'peek-right' | 'run' | свои шаги
  loop: false,
  reducedMotion: 'auto',        // 'auto' | 'force' | 'off'
  edgeInset: { bottom: 16 },    // см. «Край и карточка» ниже
  edgeRadius: { bottom: 30 },   // радиус верхних углов этой карточки
  autoplay: 'idle',             // начать, когда страница освободится (≤ 600 мс) — так в приложении
  onEnd: () => showButtons(),   // один раз за показ
});
// или без autoplay: stage.playWhenIdle() (или stage.play() — сразу)
```

Или custom element (сам стартует; `autoplay="idle"` — когда страница освободится, `autoplay="false"` —
ждать `el.play()`). В отличие от `<bunprise-mascot>`, он **не** регистрируется при импорте — так код
сцены не попадает в бандлы экранов, где её нет (проверено: импорт только `Bunny` → сцена вырезается
tree-shaking'ом):

```ts
import { defineWelcomeElement } from '@bunprise/mascot';
defineWelcomeElement(); // один раз
```

```html
<bunprise-welcome choreography="welcome" autoplay="idle" edge-inset="0 0 16 0" edge-radius="0 0 30 0"></bunprise-welcome>
```

Атрибуты: `bunnies`, `choreography`, `loop`, `reduced-motion`, `edge-inset` и `edge-radius` (как CSS
margin: `"16"` — все края, `"0 0 16 0"` — только низ), `autoplay` (`idle` / `false`). Экземпляр:
`el.stage`. Событие `welcome-end` (всплывает) — когда хореография закончилась.

### API

| Что | Описание |
| --- | --- |
| `play()` | играть с текущего момента; после `stop()` или после конца — с начала |
| `playWhenIdle(timeout = 600)` | `play()`, когда страница освободится (`requestIdleCallback`, не позже `timeout` мс; без него — через 200 мс). `play` / `pause` / `stop` / `seek` / `destroy` до этого отменяют ожидание |
| `pause()` | заморозить кадр |
| `stop()` | остановить и перемотать на 0 (пустая сцена), `onEnd` не вызывается |
| `seek(seconds)` | **детерминированно** заморозить кадр: всем анимациям ставится одинаковый `currentTime` (для скриншотов) |
| `setReducedMotion(mode)` | поменять режим на лету |
| `sample(t?)` | стили каждой анимированной части в момент `t` (из тех же ключей, что и анимации; для тестов) |
| `destroy()` | убрать всё: анимации, observers, таймеры, Shadow DOM |
| `duration`, `time`, `playing`, `ended`, `reducedMotion`, `actorCount`, `animations` | состояние |

Опции: `bunnies` (по порядку появления в `welcome`: [0] главный, [1] снизу слева, [2] из-за правого
края, [3] перебегает; по умолчанию `fawn, himalayan, choc, broken`), `choreography`, `loop`,
`reducedMotion`, `onEnd`, `autoplay` (`true` — сразу, `'idle'` — когда страница освободится),
`edgeInset` и `edgeRadius` (число или `{ bottom, left, right, top }` в px), `minSize` / `maxSize`
(ширина главного кролика, по умолчанию 96–300 px).

### Геометрия

- Сцена заполняет хост (`:host { position: relative; overflow: hidden }`), **края хоста — края
  экрана**, за которыми прячутся кролики. Всё обрезается по хосту. Высоту хосту задаёт приложение.
- Размер: главный кролик ≈ 36 % высоты сцены (виден от ушей до края), но не шире ~половины
  ширины; ограничен `minSize`/`maxSize`. Остальные — 0,8 (выглядывающие) и 0,62 (бегущий) от него.
- **Край и карточка.** Если под сценой карточка (кнопки входа), сделай хост на N px ниже верха
  карточки и передай `edgeInset: { bottom: N }`: тело кролика прячется **за** линией края, а лапки
  лежат **на** карточке поверх линии — как на иконке (с маленькой тенью от лапки, только пока
  лапка лежит на краю). Лапка, которая поднимается или уходит, проходит за краем (у каждой лапки
  две копии: «за краем» и «на краю», видна одна).
- **Скруглённые углы карточки.** Передай ещё `edgeRadius: { bottom: R }` (радиус её верхних углов):
  нижний контур обрезки повторяет контур карточки — прямая и две четверти окружности (статичный
  `clip-path: path()`), — и кролик у угла прячется за дугу, а не за невидимую прямую над фоном.
  `top` — так же для шапки со скруглёнными нижними углами. Без `edgeInset` радиус ничего не меняет.
- Сбоку кролик выглядывает «из-за дверного косяка»: стоит за боковым краем на нижней линии и
  повёрнут на 3/4 в сторону сцены (одобренный поворот: у правого края `turn-l`, у левого `turn-r`;
  `turn: false` — без поворота). Видно ближний глаз, нос и всю мордочку (подушечка ≥ 2,5 px внутри),
  дальний глаз и дальнее ухо всегда за краем (≥ 2 px; наполовину срезанный глаз или нос читались
  как странный знак). Поэтому повёрнутый кролик почти не двигает мордочку: взгляды — 1,5 единицы
  вместо 4, «на тебя» — без сдвига, без наклона тела, подъём без перелёта (за всю стойку
  мордочка сдвигается ≈ 1,2 px). Лапки держатся за косяк **пальчиками в сцену**: лапка развёрнута,
  её кончик на 11 единиц внутри края — видно ≈ 55 % лапки и все три линии пальчиков, на подходе
  лапка выползает из-за края пальцами вперёд (у тёмных лапок гималайского пальчики светлые).
  Боковые лапки рисуются только «за краем» (в обрезке): что за карточкой — то скрыто.
  Вариант `floor: false` + `pos` — лёжа на боку на любой высоте (уши свисают по гравитации).
  Сверху (`top`) — вверх ногами (работает, но в пресеты не взято: висящие уши читаются как ноги).
- **Кролик сбоку у скруглённого угла карточки** (`edgeRadius`) стоит ниже: ноги уходят за карточку
  на min(радиус, 30 px, 20 единиц) — низ тела прячется за дугу угла, а не срезан прямой линией
  над фоном. Ограничение 20 единиц — чтобы обе лапки остались над карточкой и под мордочкой
  (нижняя лапка поднимается вместе с ним: всегда над линией карточки).
- Слои: край (обрезка) < лапки на краю < бегуны — бегун никогда не оказывается «за» лапкой.
- Ресайз хоста → сцена пересобирается и продолжает с того же момента — и на паузе тоже (после
  `seek` / `pause` кадр тот же, все кролики на месте; раунд 1 на паузе их терял).

### Хореографии

| Пресет | Что | Длина |
| --- | --- | --- |
| `welcome` | вся сцена, 4 кролика (меньше окрасов — меньше ролей: 3 — без кролика у правого края, 2 — бегун и главный, 1 — только главный; главный всегда в конце) | 8,05 с (4 и 3 кролика), 5,80 с (2), 4,42 с (1); дальше спокойное дыхание |
| `peek-once` | один кролик выглядывает снизу, оглядывается и **остаётся** (пустые экраны) | 2,85 с |
| `peek-bottom` | выглянул снизу, огляделся, спрятался | 3,74 с |
| `peek-left` / `peek-right` | из-за бокового края («косяк», поворот 3/4), смотрит внутрь, нюхает, прячется | 4,34 с |
| `run` | перебегает по нижнему краю: 2 прыжка (тормозит), присел и глянул на тебя, 3 прыжка (разгоняется) | 2,49 с |
| `hop-across` | волна 1: перепрыгивает весь край **без остановки** (размером с главного) — лента, первое открытие за день | ≈ 1,7 с |
| `peek-side` | выглядывает из-за правого края («косяк»), смотрит внутрь и на тебя, прячется — настройки | ≈ 3,6 с |
| `pop-up` | выскакивает справа из-за карточки (`pos` 0,8: не закрывает текст слева), смотрит на тебя, прячется — повод | ≈ 3,0 с |
| `wave` | выглядывает и машет (одобренный `greet`), остаётся — профиль | ≈ 3,6 с |
| `lost` | «потерялся»: смотрит влево-вправо-вверх, нюхает, остаётся — 404 | ≈ 5,0 с |
| `shrug` | **пожимает плечами**: обе лапки вверх с края (ладошками наружу), голова набок, уши в стороны — и шлёп обратно, остаётся — ошибки | ≈ 2,8 с |
| `sleepy` | **засыпает**: зевает (рот широко, глаза жмурятся), глаза закрываются (дуги сна), голова клонится; потом спит: глубокое дыхание, медленный кивок, плывущая «z» — юр. тексты | ≈ 4,1 с |

**Тихая жизнь после показа (волна 1):** кролик, который остаётся (`stay`), не замирает: дыхание, моргание, иногда дёргает ухом (раз в 9,1 с) и шевелит носом (раз в 6,3 с) — только петли WAAPI, без таймеров, на паузе вместе со сценой (вкладка скрыта / вне экрана). Уснувший (`sleepy`) вместо этого спит.

```ts
]
```

`peek`: `edge`, `at` (с), `pos` 0..1 вдоль края, `tilt` (°), `floor`, `reveal`, `turn`, `hold` (с от
первого взгляда до прятания, минимум), `face` (куда уже смотрит мордочка, пока кролик вылезает),
`lookFrom` (через сколько секунд после `at` начинаются взгляды; по умолчанию 1,4 — уже вылез и
успокоился), `look` (направления **экрана**: `left|right|up|down|viewer|in`, или `at:N` — на кролика N:
на его голову, на бегуна — туда, где он в этот момент), `sniff`, `greet`, `stay`, `scale`.
`run`: `at`, `from`, `pause` (0..1 или `null`), `speed`, `scale`. Не больше **4 кроликов** на сцену
(лишние шаги пропускаются с предупреждением в консоли).

**Как кролик вылезает — лапками** (от `at`; сбоку подъём короче):

- 0–0,22 с — кончики ушей;
- 0,28 / 0,36 — лапки по очереди выходят из-за края и тянутся вверх **дугой** (на вершине — на 4
  единицы наружу вдоль края, там же переходят «на край»), шлёпаются на своё место в 0,48 / 0,56
  (сплющиваются, на карточке появляется тень от лапки);
- 0,58–0,66 — **замах в лапках** («оттолкнулся от края»): левая лапка второй раз давит на край
  (1,08 / 0,90), правая после шлепка так и держится прижатой; голова в это время приседает совсем
  чуть-чуть (1 единица) — кролик ни на миг не исчезает: кончик уха всегда ≥ 3 px над краем и не
  закрыт лапками;
- 0,66–1,00 — подтягивается между лапками (сбоку 0,28 с): лапки на рывке вытягиваются (0,97 / 1,04 →
  1 к 0,82), быстрый старт, долгий мягкий подход, перелёт и пружинка (1,12 / 1,22; сбоку без перелёта —
  только пружинка сплющивания). Голова едет на композиторе, SVG-лапки в это время стоят — ничего не
  разъезжается. Снизу тело описывает маленькую дугу (+3° → −1,5° → 0), сбоку дуги нет;
- уши: отстают от рывка (через 60–90 мс), потом догоняют (+12° / −10°) и успокаиваются;
- 1,30 — моргнул, с 1,40 — взгляды. Долгий взгляд — «живое» удержание: доходит до ~90 % и потихоньку
  дальше (с наклоном тела, кроме кролика за косяком), поза никогда не замирает.

**Как прячется** («шмыг», ≈ 0,3 с): замах (чуть вверх, глаза шире, ушки прижаты) → **голова уходит
первой** (двигается с первого кадра) → лапки отпускают край чуть позже (приподнимаются над свесом и
уходят за край, на 40–70 мс позже глаз) → последними уходят уши (отстают, до ±12°).

**Уши — одна физика на всю сцену:** отклонение не больше ±14° от покоя (как в одобренном прыжке),
пик — через 60–90 мс после рывка головы. Только «нюхает» поднимает ухо выше (поза `alert`), и это
тоже «живое» удержание: ухо медленно опускается 41 → 37° и один раз дёргается.

### Тень и контур (токены приложения)

`BASE_CSS` (общий для кролика, хомяка и актёров сцены) читает два custom properties со страницы (они проходят сквозь
Shadow DOM): `--mascot-shadow` — цвет тени-эллипса под маскотом (по умолчанию прежний `rgba(70,40,15,.12)`) и
`--mascot-outline` — тонкий контур силуэта (по умолчанию `none`; толщина `--mascot-outline-width`, 1,5 px экрана).
Контур — это обводка самих фигур силуэта (тело, уши, лапки, хвостики), нарисованная **под** их заливкой
(`paint-order: stroke fill`): видна только внешняя половина. У щёчек контура нет — они нарисованы поверх тела, и их
обводка была бы дугами внутри мордочки. В приложении (`tokens.css` §6, бумажный фон): тень 0,20 и тёплый контур
`rgba(224,171,116,.5)` — иначе кремовый кролик растворяется в кремовой бумаге (блокер 17).

### Производительность и reduced motion (правила)

- Анимируются **только `transform` и `opacity`**. Ни `requestAnimationFrame`, ни таймеров во
  время анимации: одна общая временная шкала Web Animations (часы — пустые WAAPI-анимации).
- Каждая часть = одна дорожка ключей; дорожка компилируется в анимации **только на участки
  движения** (части, которые ждут, не «тикают»): обычно 3–13 одновременно активных анимаций
  (медиана 7), максимум 23 — на миг «передачи» в 2,58 (прячется гималайский + первый прыжок
  бегуна); всего 117 участков за показ. Анимации помечены `persist()` (иначе браузер сам выкидывает
  «перекрытые» заполняющие анимации, и повтор/перемотка назад ломаются).
- Кролик **появляется в DOM-отрисовке за 0,6 с до своей роли** (до этого `display: none` и без
  анимаций), после роли «сдаёт» анимации (конечные значения остаются inline) и снова
  `display: none`. После конца живут только 3 анимации покоя.
- Большие перемещения (вылезти, перебежать) и дыхание — на HTML-обёртках (композитор), мелочи — внутри SVG.
- **≈ 80 % движения — трансформы SVG-частей** (уши, лапки, сплющивание, мордочка, глаза, нос), то
  есть главный поток. Если в это время приложение занято (гидрация, авторизация), голова поедет
  плавно, а уши и лапки задёргаются и разъедутся с ней. Поэтому в приложении — `autoplay: 'idle'`
  или `playWhenIdle()`: показ начинается после первого простоя страницы (`requestIdleCallback`,
  не позже 600 мс), **не на mount**.
- Пауза, когда вкладка скрыта или сцена вне экрана (тот же `IdleScheduler`), продолжает с того же
  кадра.
- Замеры (Edge, 20.10.2026, раунд 2; раунд 1 — то же самое): **с GPU, 4× замедление CPU** — показ
  ≈ 925 мс времени задач в секунду, одобренная сцена `greet` одного маскота в той же сессии ≈ 1690;
  покой после показа ≈ 426 против ≈ 749 у idle одного маскота (на ~40 % дешевле). Кадр p95 ≈ 12 мс.
  Сборка сцены: 4× — медиана ≈ 45 мс (`peek-once` ≈ 18 мс, reduced motion ≈ 8 мс) → **создавать
  сцену после первого кадра экрана** (например, в эффекте после отрисовки), не в критическом пути.
- Размер: импорт только `Bunny` — 13,7 КБ gz (сцена вырезается), с `WelcomeStage` — 29,1 КБ gz
  (+15,4 КБ только там, где сцена используется).
- **Reduced motion** (`prefers-reduced-motion` или `reducedMotion: 'force'`): никакого движения и
  **ни одного** вызова `animate()` — статичная композиция (главный кролик выглядывает снизу, лапки
  на краю, как иконка), плавно проявляется (CSS opacity 0,45 с), `onEnd` через 0,45 с. Строится
  только 1 кролик. Если reduced motion включили во время показа — сцена сразу становится
  статичной и вызывает `onEnd`.

Работа и ответы на действия пользователя не расходуют лимит; общий лимит классов 2–4 отложен в P2 согласно next-ux-plan §9.1, п. 11. Иллюстрации и украшения не начинают движение во время ввода и прокрутки. Бюджет и выбор вариантов живут в памяти вкладки.
